# Contributing

Start with the [development guide](docs/development.md). Keep the application focused on bridging; workout dashboards and external training services are outside its current scope.

Before opening a pull request, run the formatter, linter, and test suite. For radio changes, state what hardware was tested and what remains unverified. Automated mocks do not prove over-the-air interoperability.

Bug reports should include the app version, Windows version, trainer model, dongle USB ID and driver, reproduction steps, and a redacted log excerpt. Never post device addresses, credentials, or an unredacted environment dump.

Do not commit generated executables, local logs, downloaded reference repositories, or personal hardware addresses. Release assets belong on a GitHub release.
